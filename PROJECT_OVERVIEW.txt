## 🎯 Quick Reference

### Running a Migration

**Option 1: Fastest (Windows)**
```powershell
.\quickstart.ps1 -SvnUrl "https://svn.example.com/repo" `
                 -GitHubOrg "myorg" `
                 -GitHubRepo "myrepo"
```

**Option 1: Fastest (Linux/macOS)**
```bash
./quickstart.sh https://svn.example.com/repo myorg myrepo
```

**Option 2: With Custom Config**
```bash
cp migration-config.example.json migration-config.json
# Edit migration-config.json
python orchestrator.py --config migration-config.json
```

**Option 3: Step-by-Step**
```bash
cat config.json | python agents/repository_analyzer.py
cat config.json | python agents/author_mapper.py
cat config.json | python agents/migration_executor.py
cat config.json | python agents/github_setup.py
cat config.json | python agents/push_verifier.py
```

### Monitoring Progress

```bash
# One-time status check
python monitor.py

# Continuous monitoring
python monitor.py --watch

# View logs
tail -f migration.log
```

## 🔧 Agent Descriptions

### 1. Repository Analyzer
**Purpose:** Analyzes SVN repository structure
**Input:** SVN URL
**Output:**
- Repository layout (standard/non-standard)
- Branch and tag lists
- Revision count
- Author list sample
**Duration:** 5-30 minutes

### 2. Author Mapper
**Purpose:** Maps SVN usernames to Git identities
**Input:** SVN repository
**Output:** authors.txt file
**Format:** `svn_username = Full Name <email@domain.com>`
**Duration:** 5-10 minutes
**Note:** Review and edit before migration

### 3. Migration Executor ⏰ LONGEST
**Purpose:** Converts SVN to Git
**Input:** SVN URL, authors file
**Output:** Complete Git repository
**Duration:** 10-24 hours (for 15-year repo)
**Note:** This is the main migration step

### 4. History Cleaner (Optional)
**Purpose:** Removes unwanted files from history
**Input:** Git repository, exclusion patterns
**Output:** Cleaned Git repository
**Duration:** 15-60 minutes
**Warning:** Rewrites Git history

### 5. GitHub Setup
**Purpose:** Creates GitHub repository
**Input:** GitHub org/repo names
**Output:** Configured GitHub repository
**Duration:** 2-5 minutes
**Requires:** GitHub CLI authentication

### 6. Push Verifier
**Purpose:** Pushes to GitHub and verifies
**Input:** Git repository, GitHub remote
**Output:** Verification report
**Duration:** 10-30 minutes
**Checks:** Commit count, branches, tags

## 📊 Time Estimates by Repository Size

| SVN Revisions | Total Time | Migration Step | Total Size |
|--------------|-----------|----------------|------------|
| < 10,000 | 2-5 hours | 1-4 hours | 1-5 GB |
| 10k-50k | 5-14 hours | 4-12 hours | 5-20 GB |
| 50k-100k | 13-26 hours | 12-24 hours | 20-50 GB |
| > 100k | 1-3 days | 1-3 days | 50+ GB |

**For 15 years of development:** Expect 50k-100k revisions = 13-26 hours

## ⚙️ Configuration Options

### Basic Configuration
```json
{
  "svn": {
    "url": "https://svn.example.com/repo",
    "structure": "standard"
  },
  "github": {
    "org": "your-org",
    "repo": "repo-name",
    "private": true
  }
}
```

### Advanced Configuration
```json
{
  "svn": {
    "url": "https://svn.example.com/repo",
    "structure": "non-standard",
    "trunk": "main",
    "branches": "feature-branches",
    "tags": "releases"
  },
  "github": {
    "org": "your-org",
    "repo": "repo-name",
    "private": true
  },
  "options": {
    "author_domain": "company.com",
    "clean_history": true,
    "exclude_paths": [
      "*.dll",
      "*.exe",
      "*.so",
      "build/*",
      "dist/*"
    ],
    "max_file_size_mb": 100
  },
  "workspace": "./migration-workspace"
}
```

## 🚀 Migration Phases

1. **Analysis** (5-30 min)
   - Detect repository structure
   - List branches and tags
   - Count revisions
   - Extract authors

2. **Author Mapping** (5-10 min)
   - Create author mapping file
   - Review and edit mappings

3. **Migration** (10-24 hours) ⏰
   - Clone SVN history
   - Convert to Git format
   - Map authors
   - Convert branches/tags

4. **Cleaning** (15-60 min) [Optional]
   - Remove unwanted files
   - Rewrite history

5. **GitHub Setup** (2-5 min)
   - Create repository
   - Configure settings

6. **Push & Verify** (10-30 min)
   - Push all branches
   - Push all tags
   - Verify integrity

## 🆘 Quick Troubleshooting

| Problem | Solution |
|---------|----------|
| git-svn not found | Install: `apt install git-svn` or included in Git for Windows |
| SVN access denied | Check credentials, try manual `svn checkout` |
| Out of memory | Use machine with 16GB+ RAM |
| Migration too slow | Normal for large repos (10-24 hours) |
| Wrong authors | Edit `authors.txt` and restart migration |
| Push failed | Check GitHub authentication: `gh auth status` |

## 🔐 Security Notes

- Authors file may contain email addresses
- Review history for sensitive data before pushing
- Consider private repository initially
- Use SSH keys for authentication
- Review GitHub repository settings after creation

## 💡 Best Practices

1. **Test first** with a small repository
2. **Review author mappings** before full migration
3. **Keep SVN accessible** during and after migration
4. **Don't delete SVN** immediately
5. **Monitor disk space** during migration
6. **Run overnight** for large repositories
7. **Verify thoroughly** before announcing
8. **Document the migration** for your team

## 🏆 Success Metrics

Migration is successful when:
- ✅ Commit count matches (Git log vs SVN log)
- ✅ All branches exist in GitHub
- ✅ All tags exist in GitHub
- ✅ Authors are correctly mapped
- ✅ Timestamps are preserved
- ✅ Latest files match SVN HEAD
- ✅ No errors in verification report
