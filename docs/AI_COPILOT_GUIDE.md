# Migration Copilot Guide

The optional WPF copilot helps plan, diagnose, recover, and hand over migrations.
It combines local checkpoint-aware guidance with user-requested OpenAI or
Anthropic responses. It does not operate your repositories autonomously.

## Configure and open

1. Open dashboard **AI settings**, select OpenAI or Anthropic, and enter a
   model ID available to your account and its API key.
2. Use **Ask AI assistant** in the app shell for general product help, or
   **Ask AI** on a migration row for a specific job.
3. The copilot opens in the right-side panel. Select saved chat history to
   continue a conversation, or use the plus button for a new chat.

The initial OpenAI model suggestion is a convenience, not a guarantee of
provider availability or compatibility. API usage is billed by your provider.
Model access, organization policy, network availability, and provider rate
limits apply independently of this application.

## More than free-form chat

Expand **Guided tasks and recovery advice**:

| Task | What it prepares |
|---|---|
| Diagnose | A draft requesting observed facts, possible causes, missing evidence, and read-only checks first |
| Recovery | A draft requesting a plan based on the last completed checkpoint, preserved workspace, and retry limits |
| Readiness | A draft covering tooling, space, SVN access/layout, complete authors, permissions, and cleanup risks |
| Handover | A draft checklist of completed work, unresolved issues, verification, backup/cutover, and ownership |

These buttons **only fill the composer**. They do not call AI, add a message,
or execute commands. Edit the draft and review shared context before Send.

**Local guidance** is generated by the app's rules, not by an AI provider. It
explains the current status/checkpoint: for example, late push failures can
reuse a completed import, while incomplete SVN imports repeat. It is generic
workflow guidance, not proof of the root cause.

**Refresh migration snapshot** reads the selected job from the local API and
updates checkpoint/status/error and available log context. It does not call
AI and resets log sharing to off for that refreshed chat. It is available for
newer migration-linked chats; older saved chats may require reopening Ask AI
from the job row. A failed refresh retains the old snapshot and reports that
it must not be treated as current.

The copilot is snapshot-based, not an unattended live monitor. Refresh before
requesting advice about a job that has changed since the chat opened.
Sending shows your question immediately and a contacting indicator while the
provider responds. The selected chat stays open when its title changes.
If a request fails or returns no text, the question stays visible with a
failure label and an error below the conversation; the composer restores the
question for retry. Failed turns remain in local history but are excluded from
subsequent provider requests. Switching chats while waiting saves the reply
to the chat that initiated the request.
Migration snapshots include recorded conversion time across attempts,
excluding queue/retry/offline waits. This is elapsed processing, not a time
remaining forecast; older jobs may have no historical timing.
They also include post-push verification evidence when recorded. The assistant
must distinguish imported Git ref equality from full SVN/source acceptance.
Wizard Review's separate remote assessment reads visible history, layout,
current-trunk large files, and GitHub access after confirmation; it does not
call AI or create repositories. Cancel stops queued/running migration work
outside destructive history cleanup. AI never performs Cancel/Resume itself.

## Readiness and diagnostics workflow

1. Run **Check readiness** on the dashboard, or in the migration wizard's
   Review step. It checks local tool versions, writable storage, and disk
   space without contacting SVN/GitHub.
2. Independently verify repository access, token permissions, SVN layout, and
   author coverage. Passing local checks does not prove migration readiness.
3. If a job fails, open **Details** for Overview/recovery guidance and
   searchable recorded logs. Copy or export a complete support report.
4. Open the job's Ask AI, refresh its snapshot, select Diagnose or Recovery,
   review optional logs, and Send if your data-sharing policy permits.
5. Review the proposed actions. Use the actual dashboard **Resume** control
   with a fresh GitHub token only after fixing the cause.

The assistant does not invoke Resume, create repositories, alter mappings,
delete workspaces, force-push, or run suggested shell commands. Its wording
must distinguish observed evidence from hypotheses and unverified claims.

## Sending and privacy

- Enter sends; Shift+Enter adds a newline. Sending is explicit approval;
  there is no separate acknowledgment button.
- The provider receives the submitted conversation context and the most
  recent conversation messages used by the request. Migration metadata can
  include names, URLs, status, checkpoint, error, and timestamps.
- Recent migration logs are opt-in through **Include recent logs (redacted)**.
  Review the displayed shared context every time.
- Known secret formats are redacted before sharing and in support reports.
  This is best-effort, not a guarantee that all confidential data is removed.
  Do not paste credentials, code, or repository data you are not authorized
  to disclose.
- No provider call is made by local readiness, guidance, snapshot refresh,
  or guided drafting. Normal Send makes a direct HTTPS call from WPF; it
  does not pass through the migration API.
- AI responses can be wrong. Never treat a suggestion as validated migration
  evidence or follow destructive history-rewriting advice without review.

## History and keys

Chats are encrypted with Windows-user DPAPI in
`%LOCALAPPDATA%\SVN2GitHub\ai-chat-history.dat`. Provider/model settings and
the encrypted key are stored in `ai-settings.json` in the same directory.
They are separate from the SQLite migration database.

Switching chats during a pending reply keeps the reply with its initiating
conversation. Deletion is disabled while busy. Deleting a chat removes it
from this PC's local history, not from provider retention systems.

Use **AI settings > Clear saved key** and confirm to remove the local key
while retaining provider/model and chats. Close settings to release/reset
the current assistant. Future chat needs a new key. This does not revoke the
provider key, cancel already-issued requests, or delete chat history.
Revoke a compromised key in the provider account separately.

Older saved chats are upgraded to current app capability guidance while
retaining their historical metadata/messages. They are not automatically
assigned a current migration or treated as live data.

## Portable and enterprise boundaries

Current source supports the same copilot in portable Windows x64 deployments.
AI files remain per-user even when `SVN2GITHUB_PORTABLE_DATA_ROOT` relocates API
data/workspaces. Cross-PC/user DPAPI chat or credential transfer is not
implemented. Configure credentials anew on the destination identity.

The existing ZIP predates the new copilot tasks, readiness, diagnostics, and
recent UI changes. Publish and test current source before distributing it.
See [Portable package](../PORTABLE_PACKAGE.md).

This app does not currently offer central AI policy enforcement, tenant
isolation, SSO/RBAC, provider-managed retention controls, or immutable audit
records. Follow organizational approval and provider data policies before use.
