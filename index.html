What It Does

This system automates the complex process of migrating Subversion repositories to GitHub, preserving complete history including all commits, branches, tags, and author information. Built for enterprise repositories with 15+ years of history, it handles the migration through six specialized agents that work together to analyze, convert, and verify the entire migration process.

Complete History Preservation — Every commit from the past 15+ years is preserved with full metadata
Automatic Author Mapping — SVN usernames are converted to proper Git author identities
Real-time Progress Tracking — Monitor migration status through REST API or command line
Optional History Cleaning — Remove build artifacts and large binaries to optimize repository size
Automated GitHub Setup — Creates repository and configures it automatically
Verification & Validation — Ensures migration integrity by verifying commits, branches, and tags

03

Specialized Agents

📊
Repository Analyzer
Scans the SVN repository structure, identifies all branches, tags, and revisions. Calculates repository size and estimates migration time. Outputs analysis report with recommendations.
👤
Author Mapper
Extracts all unique SVN usernames from commit history and converts them to Git author format (Name <email@domain>). Generates authors.txt mapping file for the migration.
🔄
Migration Executor
Performs the actual git-svn clone operation. This is the longest-running step (12-24 hours for 15 years). Converts every SVN revision to a Git commit with complete metadata preservation.
🧹
History Cleaner
Optional step that uses BFG Repo-Cleaner to remove large binaries, build artifacts, and unwanted files from history. Reduces repository size and improves clone performance.
🐙
GitHub Setup
Creates the target GitHub repository using the GitHub API. Configures repository settings, branch protection rules, and repository metadata. Requires a personal access token with repo permissions.
✅
Push Verifier
Pushes all branches and tags to GitHub, then verifies the migration by comparing commit counts, branch structure, and tag presence. Generates a comprehensive migration report.

Migration Timeline

For a typical 15-year enterprise repository, the migration follows this timeline:

2-5 min

Fast metadata scan of SVN structure, branches, and tags without downloading content

1-3 min

30 sec

30-60 min

Technical Details

Prerequisites

Git with git-svn — Git 2.x with SVN bridge (included in Git for Windows)
.NET 8 SDK — Builds the WPF app and ASP.NET Core API
GitHub Token — Personal access token with repo permissions
Disk Space — 20-50 GB for temporary migration workspace

API Communication

The WPF app calls the loopback API using camelCase JSON. The service validates requests, persists migration status without tokens, and queues migration work.

Migration request (illustrative)
{
"svnUrl": "https://svn.example.com/repo",
"githubOrg": "example-org",
"githubRepo": "migration-test",
"githubToken": "[provided in memory]",
"cleanHistory": false
}
API response
{
"success": true,
"id": "...",
"status": "pending",
"message": "Migration job created successfully"
}

Extending the workflow

Workflow services are implemented in C# in the ASP.NET Core backend. New steps should follow the existing dependency-injection and cancellation-token patterns, preserve token redaction, and be validated against disposable repositories.
